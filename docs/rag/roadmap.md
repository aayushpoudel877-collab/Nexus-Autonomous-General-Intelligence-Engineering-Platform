# RAG Knowledge Intelligence Roadmap

**Phase numbering is local to the RAG subsystem** and is independent of the platform-wide phase numbers in `docs/roadmap.md`.

This is a multi-phase research and engineering program. A large commit count is not a quality metric; changes should represent reviewable, tested improvements.

- **Phase 26 — Retrieval core (implemented):** contracts, normalization/chunking, tenant-scoped lexical retrieval, optional dense-score fusion, evidence packaging, citation structure checks, baseline metrics and tests.
- **Phase 27 — Persistent corpus (implemented foundation):** organization-owned document/chunk models, PostgreSQL migration, content SHA-256 deduplication, lifecycle status, bounded pagination, async persistence helpers, concurrent duplicate handling and contract tests.
- **Phase 28 — Authenticated RAG API (implemented foundation):** authenticated and role-gated ingestion, tenant-scoped listing/chunk reads/logical deletion, bounded lexical query endpoint, audit events, strict request schemas, API contract tests and security documentation.
- **Phase 29 — Embedding adapters (contract foundation implemented):** provider-neutral model/version contracts, bounded async batching, finite/dimension validation, tenant-scoped LRU cache, vector-store protocol, test-only cosine reference backend and contract tests. Concrete provider SDKs, provider-specific rate limiting/retries, durable vector indexing, API integration and PostgreSQL/pgvector migration tests remain open acceptance items.
- **Phase 30 — Hybrid ranking research (foundation implemented):** tunable BM25, weighted reciprocal-rank fusion, document filters, source diversity limits, precision/recall/MRR/NDCG metrics and query-level ranking comparisons. Reviewed datasets, query rewriting experiments and measured ablation reports remain future work.
- **Phase 31 — Document ingestion (foundation implemented):** bounded multipart uploads; allowlisted TXT/Markdown/HTML/PDF/DOCX extraction; MIME/extension and PDF/DOCX container checks; text/byte limits; parser provenance; authenticated role-gated persistence; upload audit details and parser unit tests. Malware scanning/quarantine, durable dead-letter retries, OCR, PostgreSQL endpoint integration tests and extraction-quality benchmarks remain open.
- **Phase 32 — Generation adapters (orchestration foundation implemented):** provider-neutral async contract, strict JSON answer schema, evidence-ID citation validation, explicit prompt versioning, bounded context/input/output/answer budgets, timeout and capped transient retries, usage checks, canonical abstention and contract tests. Concrete provider SDKs, exact cost ledger, API integration, streaming, and claim-entailment validation remain future work.
- **Phase 33 — Semantic grounding (deterministic baseline implemented):** caller-supplied claim-level contracts, claim-to-citation association, unknown-ID rejection, lexical token-coverage scoring, conservative negation-mismatch flags, grounded/unsupported/contradictory/inconclusive statuses, abstention recommendation, aggregate citation/grounding metrics, compatibility citation checks, and regression tests. Automatic claim segmentation, quote/span offsets, multilingual normalization, a model-backed entailment verifier, human-reviewed benchmark data, and production calibration remain open; lexical matches are not proof of entailment.
- **Phase 34 — Evaluation harness (deterministic foundation implemented):** bounded versioned JSONL golden-set and prediction loaders; duplicate/unknown-field/size validation; precision@k, recall@k, MRR, NDCG and empty-result metrics; aggregate and language/risk/tenant slices; configurable baseline regression thresholds; stable JSON reports; CLI exit codes; synthetic fixture and CI release gate. The committed datasets are small synthetic contract fixtures, not reviewed production-quality benchmarks. Claim-level support labels now produce confusion matrices, false-positive/false-negative IDs, citation-validity rates, and language/risk slices. Human-reviewed query generation, larger reviewed datasets, latency instrumentation, source-ownership leakage tests, and semantic answer-faithfulness evaluation remain open.
- **Phase 35 — Observability and governance (contract foundation implemented):** privacy-safe allowlisted audit-event schema, source lineage without raw content, deterministic idempotency keys and acknowledgement contracts for external-index deletion, bounded retention policy/expiry decisions, model-card completeness validation, data-governance guidance and tests. A durable transactional outbox/worker, live external-index deletion, storage-specific retention execution/legal holds, telemetry backend/dashboards, and human-reviewed production model cards remain open.
- **Phase 36 — Operator workbench:** ingestion health, retrieval traces, feedback triage, dataset review and controlled reindexing.
- **Phase 37 — Multilingual and low-resource retrieval (lexical fallback foundation implemented):** Unicode-normalized tokens and opt-in character n-gram coverage support scripts without reliable whitespace segmentation; the API and operator UI expose a bounded weight while the default behavior remains unchanged. Synthetic tests cover Japanese, Devanagari, weight bounds, and tenant isolation. Language detection, transliteration, stemming, human-reviewed multilingual golden sets, and measured per-language retrieval quality remain open.
- **Phase 38 — Multimodal indexing (text-representation foundation implemented):** validated captions, OCR text, transcripts, extracted text, and metadata are converted into tenant-scoped retrieval chunks with provenance. Metadata rejects common credential-key aliases, and percent-encoded asset/representation IDs prevent delimiter collisions. Provider-backed OCR/transcription, media parsing, durable vector indexing, and reviewed multimodal evaluation remain open.
- **Phase 39 — Graph-assisted retrieval (foundation implemented):** bounded tenant-scoped graph expansion from ranked seed chunks, explicit entity-to-chunk associations, edge and entity ownership checks, one/two-hop traversal with score decay, deterministic path explanations, and resource-bound regression tests. This increment adds caps for seed count, entity count, total associations, and aggregate traversal steps; it rejects malformed association containers and requires non-negative seed scores for decay. Reviewed graph datasets, measured ablations, automatic entity extraction, and durable graph storage remain open.
- **Phase 40 — Prompt-injection evaluation (marker-rule foundation implemented):** bounded deterministic marker detection, aggregate and language/risk slices, confusion metrics, and false-positive/false-negative IDs. Rules are not a security boundary; human-reviewed multilingual corpora, obfuscation coverage, and regression thresholds remain open. **Phase 41 — Bounded agentic retrieval (foundation implemented):** explicitly allowlisted read-only tools, strict argument schemas, tenant checks, per-tool and request budgets, timeouts, and bounded evidence IDs. No model planner or write-capable tool is connected.
- **Phase 42 — Tool-planning evaluation (deterministic foundation implemented):** reviewed plan fixtures, selection precision/recall/F1, forbidden-tool attempt counts, and language/risk slices. Synthetic fixtures validate the evaluator, not live planner quality.
- **Phase 43 — Untrusted tool-output handling (marker foundation implemented):** all outputs are taint-tagged as untrusted and receive diagnostic prompt-injection marker categories. Marker rules are not a security boundary and do not automatically block evidence.
- **Phase 44 — Tool-output integrity provenance (implemented foundation):** each bounded tool execution record carries a SHA-256 digest of its exact UTF-8 output and the detector-rule version used for marker metadata. This supports reproducible audit/debugging but does not establish source authenticity, semantic safety, or durable audit persistence. Durable taint propagation through API responses and audit storage remains open acceptance work.
- **Phase 45 — Safe tool provenance serialization (implemented contract foundation):** validates the output digest against exact UTF-8 text and projects bounded metadata only (tool name, digest, detector version, marker categories, output length, evidence count, and untrusted flag). Raw output and individual evidence IDs are excluded; batch size is bounded. Authenticated API response integration, durable audit persistence, and realistic security review remain open.
- **Phase 46 — Tool provenance audit bridge (implemented contract foundation):** adds a versioned audit-detail envelope that validates Phase 44 execution records through the Phase 45 serializer and emits metadata only. It rejects tampered output and trust downgrades and bounds the batch size. Database-backed persistence, authenticated execution-boundary integration, and tenant-scoped integration tests remain open.

A phase is complete only when its acceptance criteria, tests, documentation, and security review are recorded. Avoid artificial commits; use focused commits for meaningful increments.
